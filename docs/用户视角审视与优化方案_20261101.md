# 灵梭 1.0 用户视角审视与优化方案

日期：2026-11-01
审视对象：`G:\Ai\OH-WorkSpace\项目\灵梭Agent`（当前源码，Tk 桌面版，__version__ = "1.0"）
方法：只按一个普通用户的路径走一遍真实代码，记录他每一次点击、每一次等待、每一次看不懂。所有结论后面都附代码位置，便于核对。

---

## 一、一句话结论

现在的灵梭更像一份写给自己的工程验收单，还不像给用户用的工具。三个最贵的决定都不在代码里：

1. 把"出事提醒"这个核心价值，拴在 QQ 官方机器人的主动推送能力上，而这条能力平台已经收紧。
2. 把启动门槛定在管理员权限，而监控、通知、文件这三件事都不需要提权。
3. 把"证明自己没做坏事"写进了界面和文案，代价是用户每做一件事要多点两下。

## 三、七个不合理，按对用户的伤害排序

### 1. 核心能力押在一条已被平台收紧的通道上（最致命）

灵梭的主线是"程序出事了，手机叫我"。代码里的实现路径：

`runtime.py:flush_once` → `qq.py:send_text` → `POST /v2/users/{openid}/messages`，`msg_type: 0`，不带 `msg_id`。

这是 QQ 官方的**主动消息**。而 QQ 平台 2025-04-21 移除了机器人主动消息推送能力，2026-06 才以残缺形式回归：

- 私信场景：只在用户先给机器人发过消息后，按"当天 / 1-3 天 / 3-7 天 / 7-30 天"四个周期各下发 1 条，累计 4 条；
- 群聊场景：需要群主在手机端手动打开"主动推送"开关，默认关闭；
- 沙箱内：主动能力默认开放、不受频控。

也就是说，**QQ 官方机器人现在是个可靠的遥控器，不是可靠的告警器**。用户发一条指令，机器人被动回复，这条路稳定；机器人自己开口叫人，这条路在正式环境下只剩几次配额。而灵梭 90% 的场景是后者。

这解释了为什么 141 项测试全绿也发现不了问题：全部测试都用替身（`tests/` 里没有一处真实 QQ 会话），而问题恰好长在真实平台策略上。

**改法**：把"通知通道"抽成一层，先接一个真正能主动推的通道做默认，QQ 降级为可选项。可选清单与零门槛程度：

| 通道 | 用户要准备什么 | 主动推送 | 备注 |
|---|---|---|---|
| 本机托盘/弹窗 | 无 | 本机 | 零配置，可以做成默认，覆盖"我在电脑前" |
| 邮件 SMTP | 一个邮箱 + 授权码 | 是 | 手机邮箱 App 会弹通知，完全免费 |
| 群机器人 Webhook（企业微信/钉钉/飞书） | 建群，复制一个 URL | 是 | 无需审核主体，5 分钟能通 |
| Telegram Bot | 一个 token | 是 | 最稳定，需网络条件 |
| Bark / Server酱 类 | 一个 key / 一个 URL | 是 | 国内手机推送，免费额度够个人用 |
| QQ 官方机器人 | AppID + Secret + 平台配置 | 受限（见上） | 保留，定位"遥控 + 沙箱内告警" |

需要说明的是：这一条不是技术偏好问题，是产品能不能成立的问题。通道选错，后面所有界面优化都是给一条断掉的线做美化。

### 2. 强制管理员权限，技术上没有必要

`bootstrap.py:29-31` 只要不是开发参数，一律提权重启；`build_release.py` 还写了 `--uac-admin`，发行包也是每次要 UAC。

但三条主功能都不需要提权：

- 进程采集：`processes.py:list_processes` 用 Toolhelp 快照，`working_set` 用 `PROCESS_QUERY_LIMITED_INFORMATION`；
- 窗口分类：`visible_window_pids` 用 EnumWindows；
- 文件发送：`files.py` 普通读 + 句柄真实路径核验。

唯一需要管理员的是 `automation.py:WindowsMouse.click`：往"以管理员运行的游戏窗口"注入输入会被 UIPI 拦。

代价却是全局的：每次启动一个 UAC；不能走普通开机自启；受限账户（公司机、访客号、标准用户）直接不能用；插件继承管理员权限，于是界面里还得自己加一段"插件也拥有管理员权限"的警告（`desktop.py:756`）。

**改法**：默认普通权限启动，三主功能照常；只有进入"鼠标工具"或勾选"监控需提权的进程"时，提示"以管理员重新启动"（`bootstrap.py` 已经有现成的提权函数，改成按需调用即可）。顺便让开机自启成立。

### 3. 三层重复导航，7 个页面被 27 个入口指向

- 侧栏 8 项（`desktop.py:63-67`）
- 首页 4 张卡 + 每张一个"设置"按钮（`desktop.py:273-282`）
- 设置页 15 张卡 + 每张一个"编辑"按钮（`desktop.py:818-838`）

设置里的 15 项，有 7 项是跳去别的页面（QQ、进程监控、目录设置、接收人绑定、插件加载、使用帮助、两种鼠标工具），另 2 项（"通知策略"和"高级设置"）打开的是同一个窗口（`desktop.py:825` 和 `desktop.py:837` 都指向 `self.advanced_dialog`），点"通知策略"看到的是采集间隔和文件上限。

具体到最疼的一处：用户想"加一个监控程序"，他要先判断这件事属于首页、侧栏还是设置。

**改法**：设置页只留真设置（采集间隔、文件上限、搜索深度、合并窗口、重试次数、数据目录），其余入口全部回侧栏；首页 4 卡合并成一条待办清单；顶部 badge 只留 2 个，版本号进"关于"。

### 4. 确认弹窗过多，把安全做成了摩擦

逐条数过（`desktop.py`）：

| 任务 | 确认次数 | 位置 |
|---|---|---|
| 授权一个文件夹 | 目录选择器 + 1 次弹窗 | `add_root` 442-448 |
| 授权桌面 | 1 次弹窗 | `save_desktop` 427-441 |
| 保存 QQ（AppID 或环境变更） | 最多 2 次弹窗 | `save_qq` 590-610 |
| 发送一个文件 | 1 次弹窗 + 2 分钟倒计时 | `prepare_file` 476-489 |
| 确认手机已收到 | 再弹 1 次 | `confirm_receipt` 634-637 |
| 安装插件 | 1 次 + 信任 1 次 + 调用 1 次 | 771-778 / 808-815 / 779-802 |
| 保存本地文本 | 1 次 | `save_local_document` 933-941 |

其中真正"不可撤销、影响外部"的只有三类：对外发文件、授权目录、信任外部代码。其余确认（保存设置、确认收到、打开文档）是在替用户做心理安慰，每多一次就让"高频操作"变成"不想用"。

**改法**：确认分级，只保留三类；其余改成右下角就地状态条（3 秒自动消失，可点开详情），不再阻断流程。目标：日常任务（加监控、发文件）各 1 次确认、2 次点击内完成。

### 5. 状态与文案在自我解说，用户得不到答案

- 一屏之内四套状态：顶部 4 个 badge（`desktop.py:71-72`，其中一个是版本号）、banner 一行塞四个指标（`desktop.py:73,1075-1079`）、侧栏底部一句（`desktop.py:1071`）、页面内又各有一套（`monitor_note`、`file_note`、`users_note`、`qq_status`）。
- 状态语义混乱：`side_status` 用"监控线程是否存活"表示"本地核心"，而监控暂停时线程仍在跑，用户可能同时看到"本地核心运行中"和"监控未启动"。
- 错误一律 `messagebox.showerror`（`desktop.py:116-117`），文案是给开发者看的："请检查数字参数，不要留空或填写文字"、"有多个匹配目标，请缩小识别范围"。
- README 里"不代表""不会""须""仍需""不等于"密度极高，用户读完记住的是风险清单，不是产品能干什么。

用户只想知道三件事：现在有没有在盯、刚才发生了什么、出问题时点哪。

**改法**：一条状态行（未配置 / 正在盯 N 个程序 / 出错）+ 一个"最近事件"时间线（首页下半屏，替代已有的运行记录弹窗）；错误改成"问题 + 下一步按钮"，就地展示。免责声明退回文档，不进界面。

### 6. 功能账本失衡：主业 3 个，副业 6 个，其中 1 个打包版必然报错

主业：进程监控、通知、文件发送。
副业：鼠标连点、图片识别点击、本地文本编辑器、网页搜索、六套皮肤、插件机制（`desktop.py:818-838`）。

两个硬问题：

- **打包版里"图片识别点击"一定失败**。`build_release.py` 的 PyInstaller 参数里写了 `--exclude-module numpy`、`--exclude-module cv2`，而 `automation.py:TemplateMatcher` 在调用时才 `import cv2 / import numpy`，异常会被兜成"点击任务失败，已停止；请检查参数和图像组件"。界面给了一张卡，点下去只会报错。
- **插件机制对终端用户没有价值**。`desktop.py:808` 要求用户"审查代码、信任指纹、退出重启"，你是唯一作者，插件是给第三方写的接口。它占掉了帮助里一整篇、README 一大节，以及测试里一堆用例。

同时名字叫 Agent，产品里没有任何 Agent，只有监控和通知。

**改法**：鼠标工具（连点 + 图色）单独拆出去，独立窗口或独立 exe。它跟"看门 + 叫人"没有共享语境，风险属性也完全不同（会向游戏发输入）。本地文本编辑器和"发文件"是两条并行的产物，留一条。网页搜索砍。皮肤留 2 套。插件机制在个人版隐藏，只留开发版。名字要么改回"灵梭"，要么以后真做 Agent。

### 7. 工程侧让界面"用不动"的细节

| 现象 | 证据 | 后果 |
|---|---|---|
| 单文件 1180 行、单类一百多个方法 | `desktop.py`（83 KB，`class DesktopApp` 从 17 行到 1176 行） | 改一处要读全篇，回归靠人眼 |
| UI 线程每 300ms 全量刷新 | `desktop.py:265` `self.root.after(300, self._poll)`；`refresh()` 里调 `app.status()`（`runtime.py:status` 会查 SQLite 的 tests/history/queue）并重建 15 张卡摘要，`filter_processes()` 每次重建整个进程表字符串 | 输入发涩、拖动窗口掉帧，进程多时更明显 |
| 全局 busy + 单线程池 | `desktop.py:25` `ThreadPoolExecutor(max_workers=1)`；`button()` 101-114 处 busy 时静默 `return` | 刷新进程那 1-2 秒里，除退出/托盘外所有按钮点了没反应，也不变灰 |
| 勾选用文本 ☑/☐，只有第一列能点 | `desktop.py:341`、`348-351` | 点程序名没反应，空格还要先选中行 |
| 点导航会清空正在填的表单 | `desktop.py:66` 侧栏"绑定 QQ 机器人"走 `open_notifications()` → `reset_qq_form()`（`desktop.py:534-539`） | 填到一半点侧栏，AppID/OpenID 全被重置，密钥也被清空 |
| 单实例冲突只有一句 MessageBox | `app.py:33-40` + `bootstrap.py:46-48` | 用户已有一个实例在托盘时，只得到一句"请从托盘打开主窗口"，没有"帮我打开"的按钮 |
| 测试数字指向的是已经弃用的界面 | 141 个用例，`test_core.py` 44 个、`test_guidance.py` 28 个里有大量 `from lingsuo.panel import serve`（web 面板），而交付界面是 Tk，`ui/`（48 KB）与 `lingsuo/panel.py`（182 行）已不从主入口导入 | "111 项通过"给人完成感，但对用户实际摸到的界面几乎不设防 |
| 文档承诺与实际不符 | `docs/真实引导与帮助中心_交付记录.md` 写"可搜索的 8 个主题"，Tk 版帮助是 `Listbox + Text`，没有搜索（`desktop.py:1022-1053`） | 用户照着文档找搜索框，找不到 |
| 交付物是旧包 | README 自述 release/dist 未更新，当前是 `pythonw.exe` 跑源码 | 想分发时，用户看到的是 UAC + 免责声明 + 一张会报错的卡 |

## 四、优化方案

原则：先让产品成立，再让产品好用，最后让产品能发。三阶段之间不并行，P0 不通过不进入 P1。

### P0 决定死活（1-3 天，改动集中在通道与启动）

**P0-1 通知通道分层**
- 新增 `lingsuo/notify/` 目录，定义最小接口：`send(text) -> 平台是否接受`。
- 三个 provider 先落地：`tray`（默认，零配置）、`smtp`（一个邮箱 + 授权码）、`webhook`（企业微信/钉钉/飞书群机器人，一个 URL）。
- `qq` 保留为第四个 provider，界面标注"适合遥控与沙箱内告警，正式环境主动消息配额受限"，把限制写清楚，而不是让用户自己撞。
- 配置里把 `qq` 段拆成 `channels: [{kind, enabled, settings}]`，旧配置做一次迁移（`config.py:validate` 已经在做加法迁移，按同样方式加一段）。
- 验收：新用户在**不碰 QQ** 的情况下，5 分钟内让手机响一次（托盘 + 邮件双通），并且断开网络时状态显示"未送达"而不是"已发送"。

**P0-2 启动不强制 UAC**
- `bootstrap.py` 默认不提权；新增 `--elevate` 参数，由"鼠标工具"和"提权监控"入口调用。
- 打包脚本去掉全局 `--uac-admin`，改为普通清单。
- 验收：标准用户账户能完成监控 + 托盘 + 邮件全链路。

**P0-3 首页改成一句话 + 一个按钮**
- 顶部一句产品定义（例如"游戏或程序掉线了，手机叫你"）。
- 一个主按钮"盯住一个程序"，三步：选程序（搜索框预填最像目标的那几个）→ 选通道（默认托盘，可加邮件）→ 完成。
- 4 张待办卡降级为右侧小清单，可选。
- 验收：从双击到进入"正在盯 1 个程序"，≤ 8 次交互、不打开浏览器。

### P1 削摩擦（约一周）

**P1-1 设置页只留真设置**，其余入口回落侧栏；首页 4 卡合并为待办清单；badge 只留"通道状态 / 监控状态"，版本号进"关于"。
**P1-2 确认分级**：只保留对外发文件、授权目录、信任代码三类弹窗，其余改就地状态条。
**P1-3 单一状态源**：一条状态行 + 首页"最近事件"时间线；停用 `banner` 与侧栏底部重复状态。
**P1-4 交互细节修复**：进程表整行可点、真复选框、双击直接加入；`busy` 从全局改为按钮粒度（自身转圈 + 禁用，不冻结其他操作）；`refresh` 改事件驱动 + 1 秒心跳，`status()` 结果缓存，SQLite 查询移到后台线程。
**P1-5 修掉"点导航丢输入"**：`open_notifications` 只在首次进入或用户点"取消更改"时重置表单。
**P1-6 单实例**：检测到已有实例时，给出"打开已运行的灵梭"按钮（通过命名事件或窗口枚举唤出），而不是只说一句提示。

验收：日常任务各自 ≤ 2 次点击、无阻断式弹窗；1000 个进程 + 5 秒采集下，界面刷新时主线程耗时 < 10ms。

### P2 产品化（两周到一月）

**P2-1 拆功能**：鼠标工具独立窗口/独立 exe；本地文本编辑器并入"发文件"或删除；网页搜索删除；皮肤保留 2 套；插件机制只在开发版可见。
**P2-2 拆代码**：`desktop.py` 拆成 `pages/home.py|monitor.py|files.py|notify.py|settings.py`、`widgets.py`、`state.py`、`dialogs.py`；把被弃用的 `panel.py` / `ui/` 从主测试套件移到 `tests/legacy/`，让 141 个用例重新指向真实界面。
**P2-3 打包与分发**：签名、安装器、首启自检、升级检查。打包要么带上 numpy/cv2（如果你保留图色），要么不显示那张卡。卡密/授权放到这一步之后，因为 UAC 和通道问题不解决，售后成本会吃掉利润。

### 明确不做

- 不再加新的功能卡（在现有的账本失衡修好之前）。

## 五、可量化验收

| 指标 | 现状（按代码推算） | 目标 |
|---|---|---|
| 首次可用时间（双击到收到第一条自己制造的通知） | 30 分钟以上，且依赖平台审核 | ≤ 3 分钟 |
| 首次可用交互次数 | 约 18 | ≤ 8 |
| 是否需要打开浏览器 | 必须 | 不必须 |
| 日常任务点击数（加监控 / 发文件） | 3-5 | ≤ 2 |
| 阻断式弹窗（除三类不可撤销操作） | 7 类任务共 9 次 | 0 |
| 真实账号闭环验证 | 0 次 | 1 次（通道 + 主动推送 + 文件） |
| 主线程刷新耗时（1000 进程） | 每 300ms 重建全表 | < 10ms，且按事件触发 |

真实账号闭环这一条必须做，且必须由你本人操作。现在全部测试都是隔离替身，而产品死掉的风险恰好落在唯一没测的那一段。

## 六、风险与依赖

1. **平台政策是外部变量**：QQ 主动推送的配额与开关、沙箱成员限制、个人主体不能公开使用，都不在你手里。多通道不只是体验优化，是风险对冲。
2. **提权是信任成本**：一个"帮你看着程序"的工具每次要 UAC，用户第一反应是"它要干什么"。把提权押后，等于把信任门槛降低一档。
3. **反复重写的历史**：从 LataleGuard 到 web 面板再到 Tk 桌面，`docs/` 里留下三份"交付记录"。这次如果继续用"再写一份交付记录"的方式推进，很可能又得到一次重写。建议这次按验收指标推进，写记录之前先跑通一次真实闭环。
