## 一、结论

## 二、这轮确实变好的地方

先说公正的，这几条值得保留，不要在后续瘦身时误删：

1. **主动推送的现实被承认了，而且做了工程处理**。`store.remember_reply / reserve_reply` 用"用户近期消息 + msg_seq 序号"走被动回复窗口（5 分钟、最多 5 个序号、队列留 3 个），等待时明确显示"请向机器人发送状态"，24 小时过期，网络不确定记"结果待核对"且不自动重发。这是对平台约束的诚实处理，比假装能推送强得多。
2. **没有再生成第二套状态**。通知队列直接映射成 N 开头任务（`tasks.notification_rows`），而不是另开一张表编一个"已发送"。这个决定很正确。
3. **新服务全部默认关闭，授权独立，失败不虚报**。观察、异常、附件接收都默认关；采集失败保留基线、不当成退出；日志只报命中次数不复制正文；下载只允许指定 QQ CDN 的 HTTPS 地址。
4. **危险动作有前后闸**：预览 5 分钟有效、执行前校验 sha256、同名拒绝覆盖、备份 + 恢复编号、恢复前再次核对授权。
5. **测试仍然把"真实未验收"单列**，没有把隔离结果冒充实机结果。

这些是工程诚实度的体现，跟"好不好用"是两个维度，要分开看。

## 四、这轮新增的六种用户负担

### 1. 门槛更高了，而不是更低

- 首用：README 现在是 9 步编号，其中 4 步在 QQ 平台侧。
- 设置：21 张卡（`desktop.py:849-870`），其中 7 张是跳转入口，2 张指向同一个窗口，2 张是鼠标工具。
- 帮助：15 篇。步骤正文里出现"设置 → 高级设置""设置 → 进程异常规则"这类路径描述，本身就说明界面不能自解释。
- QQ 指令：开启 / 绑定 / 停止 / 订阅 / 退订 / 状态 / 历史 / 测试通知 / 接收 / 接收 N / 任务 / 我的任务 / 任务 X / 取消任务 X / 收到任务 X / 取消 / 发送 / 确认发送 X / 我的ID / 帮助，共约 18 种说法。

一个新用户面对的是 35 个入口、21 张设置卡、15 篇帮助、18 条口令。这套东西的学习成本已经超过它省下的操作。

### 2. 告警变成"要你先说话"的告警

用户的期待是：游戏崩了，手机响。现在的实际链路是：游戏崩了 → 本机记录 → 队列里等 → 只有该接收人 5 分钟内给机器人发过消息，才有上下文能发，且队列里只剩 3 条配额用完就继续等。

代码里这个逻辑很清楚（`store.reserve_reply` 取 `seq<5` 且 `ts>now-300`；`runtime.flush_once` 取不到就 `defer`）。产品上也认了（README「QQ 的实际边界」一节）。

问题在于：这不是"边界"，这是"核心场景不成立"。一个用来"出事了提醒我"的工具，要求"出事前 5 分钟内我刚跟它说过话"，那它提醒的是"我说话之后发生的事"，而不是"我不在的时候发生的事"。

这一轮的正确做法应该是在承认约束的同时补一条真正能主动推的通道，而不是把约束写进帮助和 README。文档写清楚风险，不等于把风险从产品里消掉。

### 3. 授权模型从 1 套变成 5 套

现在有五个互不相干的目录范围：

| 范围 | 配置位置 |
|---|---|
| QQ 共享目录 + 桌面 | 文件发送页 |
| 仅本机资料目录 | 设置 → 本机数据 |
| 观察目录 / 日志文件 | 设置 → 文件监控与日志 |
| QQ 接收目录 | 设置 → QQ 附件接收 |
| 本机文件管理目录 | 本机文件页 |

读者要自己记住：同一个文件夹，在"文件发送"里授权了 QQ 能读，在"本机文件"里授权了软件能改，在"观察"里授权了软件能轮询，在"接收"里授权了能写入，四者互不继承。用户理解不了，就会全部授权一遍，等于把授权模型废掉。

### 4. 任务状态机外露成用户词汇

`tasks.py:STATE_NAMES` 有 9 个状态：等待、执行中、执行完成、平台已接受、已取消、超时、失败、上次中断、结果待核对。加上 N 开头编号、"收到任务 编号"确认、取消是"协作停止"。

用户要的是三个词：成了、没成、还不确定。现在是九个，还要区分"平台已接受"和"用户已确认收到"。

工程上这套分得很对（发送确认和送达确认确实不能混）。产品上不该让用户背这套，应该折叠成一句人话 + 一个可展开的详情。

### 5. 危险动作进了门，信任门槛没跟着解决

这一轮让程序获得了：移动、重命名、按扩展名批量整理、覆盖保护、备份、恢复、文档转换。这些是真正会改动用户磁盘文件的能力。

同时它仍然是：每次启动弹 UAC、插件拥有宿主权限、备份没有自动清理（README 自己提醒"注意磁盘空间"）。

功能危险等级上去了，信任门槛一点没降。正常的产品顺序是先降低信任门槛（不提权、可审计、可一键回滚），再加危险动作。

### 6. 命名开始撞车

- "文件发送"（发给 QQ）与"本机文件"（本机管理）两页名字太近，用户分不清哪个是给手机取文件、哪个是整理磁盘。
- "鼠标工具"在侧栏有一页，在设置里又有两张卡（`mouse`、`image`）。
- "通知策略"和"高级设置"打开同一个窗口。

## 五、优化方案（这一版把顺序钉死）

### 第 0 步：冻结新增能力（立即生效）

接下来两周，不加新服务、不加新指令、不加新设置卡。理由：现在每加一个能力，入口数、授权数、状态数、口令数都跟着涨，而首屏价值仍然是零。继续加宽会先把产品压垮。

### P0 让产品成立（2 天，只碰三处）

**P0-1 加一个真正能主动推的通道，与 QQ 并列**
- 最小实现：`tray`（零配置，界面上弹一条，覆盖"我在电脑前"）+ `smtp`（一个邮箱 + 授权码，手机邮箱 App 会推）+ `webhook`（企业微信/钉钉/飞书群机器人一个 URL）。
- 通知层做成 `send(text)` 三行接口，QQ 保留为其中一个 provider，保留现有的被动回复窗口逻辑。
- 界面文案改成一句实话：QQ 适合遥控与沙箱内提醒；要手机随时响，用邮件或群机器人。
- 验收：新用户不碰 QQ，5 分钟内手机响一次；断网时状态显示"未送达"。

**P0-2 默认不提权**
- `bootstrap.py` 默认普通权限；`--elevate` 只在"鼠标工具"和"提权监控"入口调用；打包去掉 `--uac-admin`。
- 四条主功能（进程、文件、观察、本机管理）在标准账户下必须全通。
- 验收：标准用户账户跑完整链路；开机自启可用。

**P0-3 首页改成一句话 + 一个按钮**
- 一句产品定义 + 一个"盯住一个程序"的主按钮（选程序 → 选通道 → 完成）。
- 4 张"待设置"卡降级成右侧小清单。
- 验收：双击到"正在盯 1 个程序"，≤ 8 次交互、不打开浏览器。

### P1 削摩擦（一周）

1. **一张权限表替代五套授权**：新增"范围"页，一行一个文件夹，行内四个勾选：允许 QQ 读取 / 允许观察 / 允许本机管理 / 作为接收目录。底层五个配置段不动，只是给用户一个统一的管理面。这一条直接消掉"授权模型爆炸"，也顺手解决"同一个目录要在四处分别授权"的困惑。
2. **任务状态折叠成三个词**：成 / 未成 / 待核对，详情展开看 9 个内部状态。列表默认只显示编号、操作、一句话结果。
3. **设置页从 21 张收到 7 张**：只留真设置（采集间隔、文件上限、搜索深度、合并窗口、重试次数、通知通道、数据目录），其余入口全部回侧栏或"范围"页；鼠标工具只在侧栏留一处。
4. **去弹窗**：只保留"对外发送 / 授权目录 / 信任代码"三类阻断确认，其余就地状态条。
5. **修四个具体硬伤**：点导航不再清空表单；进程表整行可点 + 真复选框；`busy` 改按钮粒度；`refresh` 事件驱动 + 1 秒心跳，`status()` 与 `tasks.recent()` 结果缓存，SQLite 查询移出 UI 线程。
6. **命名**："文件发送"改"发给手机"，"本机文件"改"本机整理"，两个概念一眼分开。

验收：日常任务（加监控、发文件、整理一次）各自 ≤ 2 次点击、0 次阻断弹窗；1000 进程下主线程刷新 < 10ms。

### P2 产品化（两周到一月）

- 代码拆分：`desktop.py` 按页拆（home/monitor/files/notify/settings/range/tasks），`desktop_services.py` 的分号流按功能展开；弃用的 `panel.py` / `ui/` 从主测试套件移出，让 186 项测试重新指向真实界面。
- 功能归属：本机文件管理 + 文档转换 + 网页读取 + 工具编排合成一个"工具"页或独立 exe；个人版隐藏插件机制。
- 交付：打包（要么带上 numpy/cv2，要么不显示图片识别卡）、签名、安装器、首启自检。卡密与发卡放到这之后。

### 明确不做

- 不再加新服务、新指令、新卡片（第 0 步）。
- 不做模拟事件、演示数据（会制造假成功）。
- 不做云端、LLM、通用规划器（`docs/工具与任务协议.md` 里那条 1-10 步固定编排先冻住，等真实用户跑过再说）。
