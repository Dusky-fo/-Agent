# 工具与任务协议（本机固定规则，1.0）

入口为 Runtime.tools（ToolExecutor），复用现有 Registry 的参数校验。清单字段：name、version、description、parameters、permissions、origins。参数仅支持有界字符串、整数和布尔值，未知键拒绝；本轮不接受可执行脚本、命令行或由参数提供的身份/授权。

调用身份 Caller(owner,origin,permissions) 由宿主构造；只有本机交互确认后才传入写入或网页权限。QQ入口只处理本人任务查询/取消、授权文件收发及已有通知命令，不允许files.write/web.read/plugins.execute。受信Python可自行绕过应用层检查，因此此协议不是沙箱。

TaskContext 提供 id、owner、check()、progress(percent,step)。check在检查点验证取消和单调时钟deadline；不能杀死线程、阻止已完成的外部提交，也不能保证阻塞调用瞬时取消。HTTP超时单独有界，文件读写按块检查。

结果为 JSON 对象（≤1MB，超出保留摘要），包含实际结果而非假记录。终态包括 completed、platform_accepted、cancelled、timed_out、failed、uncertain、interrupted；用户实际确认收到单列 received 时间。错误记录使用安全用户提示，不持久化原始传输响应、令牌或签名URL。网页公开文字和本机搜索路径可进入本地任务结果，不能分享真实数据库。

当前注册工具：files.search(files.read)、files.apply/files.recover/documents.convert(files.write)、web.read(web.read)、tasks.status(tasks.read)、plugins.invoke(plugins.execute)。写工具还在实际执行层重新验证本机目录授权、单次预览/授权及内容摘要。documents.convert必须提交已预览SHA256；web.read还必须提交本机逐次授权的完整URL单次令牌，不能复用或换URL。

workflow(steps,caller,timeout)接收1–10个{tool,parameters}步骤，先预检所有工具、参数和权限，再顺序执行；每步检查取消和超时，返回有序结果。没有自动规划/LLM、动态脚本、图形化编排编辑器和跨步骤事务；失败保留先前已完成结果，文件变更通过恢复编号恢复。插件运行不能强制中断，重启才完全停止其副作用。

QQ文件、附件、本机文本保存、鼠标任务沿用各自既有执行器并接入同一Tasks；通知直接读写现有outbox，N开头ID可查询/取消尚未提交项。已开始的通知请求不能撤回。通知队列没有有效被动回复上下文时等待，最多24小时。程序重启未结束的普通任务记interrupted、提交中的通知记uncertain，不自动重复执行。

Agent、浏览器登录/授权表单执行器可将来以独立能力增加，但现在没有这些实现，也不会因为Caller里写了某个权限名就自动获得不存在的执行器。Render及任何云端业务配置不涉及本协议。
